# 概要

## 目的

PC の Obsidian で書いた Markdown のノートを、スマホでも読みやすく見られるようにする。端末の間の同期で困らないようにし、狭い画面でも読みやすく表示する。

## 使う人

本人だけ。許可した Google アカウントでログインする。許可するメールアドレスは、あとから足せる。

## 主な機能

- Google アカウントでログインできる（許可したメールアドレスだけ）
- フォルダのツリーからノートを選べる（コンテンツフォルダの構成そのまま。ファイル名・フォルダ名に日本語があれば、URL にも日本語のまま使う）
- 最初に開く画面：コンテンツフォルダの一番上に `index.md` があればそれを、なければツリーと案内を出す
- ノートを読みやすく表示できる
  - フロントマターは本文に出さない。`title` があれば見出しに使い、なければファイル名を使う
  - コールアウト：Obsidian 標準の種類（note、tip、warning など）と、折りたたみ（`> [!note]-`）
  - コードのハイライト、表、数式、Mermaid、画像（相対パス）
- ノート内の目次（見出しの一覧）を出せる
- ノートの中の相対リンク（`[表示名](../folder/note.md)`）から、別のノートへ移れる。リンク先がないときは「ノートが見つかりません」と出す
- ライトとダークを切り替えられる
- 本文の文字の大きさを変えられる（px の値から選ぶ。初めは 14px・16px で、標準は 16px。端末ごとに覚えておく）
- ログアウトできる（ノートの一覧のいちばん下から）

## やらないこと

- ノートの編集（アプリでは読むだけ。ノートはリポジトリに置いて更新する）
- 検索（初期の段階では作らない）
- Obsidian の保管庫との同期、`[[ ]]` 記法の解釈（リポジトリに置く前の加工で、ふつうのリンクに直してある前提）
- フロントマターの `title` 以外の項目（タグなど）を使うこと（後回し）
- 複数のユーザーの管理、データベース
- ノートを外部に公開・共有すること

## 技術

| 用途 | 使うもの | 選んだ理由 |
| --- | --- | --- |
| 言語・フレームワーク | Next.js（App Router）＋ TypeScript | ログインの仕組みと組み合わせやすく、ノートをビルドのときに HTML にしておける |
| デプロイ先 | Vercel（Hobby） | push するだけで反映され、Next.js と相性がよい。個人で商用でない用途なので Hobby で足りる |
| 認証 | Auth.js ＋ Google ログイン。許可するメールアドレスは環境変数に並べる | 合意したログインの画面をそのまま作れる。アドレスは環境変数を変えて再デプロイすれば足せる |
| ノートの置き場所 | このリポジトリの `content/` フォルダ。ビルドのときに全部のノートを HTML にする | 表示が速く、壊れたリンクもビルドの時点で分かる。GitHub の API やトークンが要らない |
| Markdown の変換 | unified（remark・rehype）。フロントマターの読み取りに yaml、数式の読み取りに remark-math。コードの色分けに highlight.js、数式に KaTeX（どちらもビルドのときに HTML にする） | Next.js・MDX の定番で、構文の木に手を入れて、リンクの書き換え・コールアウト・目次などを同じ仕組みのプラグインで足せる。highlight.js と KaTeX は同期で動き、変換を同期のまま保てる |
| 図（Mermaid） | mermaid（ブラウザで描く） | ビルドのときに描くにはビルドの環境にブラウザが要り、Vercel のビルドでは重い |
| データベース | 使わない（ログインの状態は暗号化した Cookie に持つ） | 読むだけで、保存するデータがない |
| UI の部品ライブラリ | 使わない（Tailwind CSS ＋ 自分で作る部品） | 要る部品が少なく、プロトタイプで決めたトークンをそのまま使える |
| 状態管理 | 使わない（ダークと文字の大きさは、ブラウザに保存する） | 端末ごとの設定だけで、画面をまたいで共有する状態がない |
| 個人情報 | 許可するメールアドレスは Vercel の環境変数にだけ置く | コードやリポジトリに書かないため |
| テスト | Vitest ＋ Testing Library。画面の画像を比べるテストは Playwright | Next.js 16 の構成で設定が少ない Vitest と、画像の比較と公式の Docker イメージがそろう Playwright |

## 用語

| 用語 | 意味 |
| --- | --- |
| ノート | md ファイル1つ |
| コンテンツフォルダ | リポジトリの中で、ノートを置くフォルダ。この中の構成がそのままツリーになる |
| 教材 | コンテンツフォルダの一番上の、教材ごとのフォルダ。入口（`index_<教材名>.md`）・学習ガイド（`00_ガイド.md`）・章（`01_<題>.md` から）からなる。決まりは `docs/content-rules.md` |
| コールアウト | `> [!note]` のように書く、囲みの強調表示 |
| フロントマター | ノートの先頭の `---` で囲んだ YAML |
| 目次 | ノートの見出しの一覧。押すとその見出しへ移る |
| ノートの一覧 | コンテンツフォルダの構成そのままの、フォルダとノートのツリー。スマホでは ☰ で開き、PC では左に常に出す |
| ホーム | 最初に開く画面。`index.md` があればそれを、なければノートの一覧と案内を出す |
| 上の帯 | 画面の上に固定する帯。☰、場所（パンくず）、目次・文字の大きさ・ライト/ダークのボタンを置く |
