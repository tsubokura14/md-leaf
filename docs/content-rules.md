# content/ の決まり

`content/`（コンテンツフォルダ）に教材を置くときの決まり。教材は Obsidian の保管庫で作り、ここへコピーして入れる。ノートの正本は保管庫のほうにある。

- 決まりに合うかは、検査のコマンド（`npm run check:content`）が機械的に確かめる。`npm run lint` の中でも走るので、合わないものがあると CI で止まる
- ノートの中身（内容が正しいか、スマホで読みやすいかなど）は、精査のコマンド（`/content-review`）でサブエージェントが確かめる
- 決まりを `content/` の中（`README.md` など）に書かないのは、アプリにノートとして出てしまうため

## 置いてよいもの

- ノート（`.md`）と、アプリが表示できる画像（png・jpg・jpeg・gif・webp・svg。拡張子の大文字・小文字は問わない）だけ
- 名前が「.」で始まるファイル・フォルダ（`.claude/`、`.obsidian/`、`.gitkeep` など）は置かない
  - 理由は `docs/design.md` の「`content/` には決まりに合うものだけを置く」

## 名前と並び

今の教材の形をそのまま決まりにしている。

### 一番上

- ホームの `index.md` と、教材ごとのフォルダだけを置く
- `index.md` には、すべての教材の入口（`index_<教材名>.md`）へのリンクを置く

### 教材のフォルダの直下

| ファイル | 決まり |
| --- | --- |
| 入口 | `index_` で始まる `.md` をちょうど1つ（例：`index_python基礎.md`）。`<教材名>` はフォルダ名と同じでなくてよい（空白を除く・`_` に変えるなど） |
| 学習ガイド | `00_ガイド.md` |
| 章 | `<2けたの番号>_<題>.md`（例：`01_Pythonの基本と実行のしかた.md`）。番号は 01 から抜けなく続け、重ねない |

- 直下には、上の3種類のほかにファイルを置かない

### 下のフォルダ

- 章でないノートと画像は、教材のフォルダの下のフォルダに置く（`図`・`暗記用`・`演習`・`早見表`・`テンプレート` など。名前は決めず、増やしてよい）
- 下のフォルダのファイル名には、番号の決まりを付けない（`演習/02_模擬問題1_パート1.md` のように、同じ番号を枝分かれで使ってよい）
- 中に置いてよいのは、ノートと画像だけ

### すべてのノート

- フロントマターに、空でない `title` を書く（見出しと一覧の名前に使う）

## 書き方

アプリでは表示できない書き方を使わない。検査で見つける。

- `[[ ]]`・`![[ ]]`（Obsidian のリンクと埋め込み）を、コード・数式の外に書かない。ふつうのリンク `[表示名](../folder/note.md)` と画像 `![説明](図/xxx.svg)` に直す
- 相対リンク・相対パスの画像は、`content/` の中にある先を指す（リンク切れにしない）

## 足し方の手順

1. 保管庫で教材を作り終えたら、教材のフォルダを `content/<教材名>/` へコピーする
   - 保管庫から一緒に来る作業ファイル（`.claude/` など「.」で始まるもの）は、コピーしない
2. `content/index.md` に、新しい教材の入口へのリンクを足す
3. `npm run check:content` を実行する。一覧に出たものを直し、通るまでくり返す
   - ノートの中身を直すときは、保管庫のほうで直してからコピーし直す（ここだけ直すと、保管庫とずれる）
4. `/content-review content/<教材名>` で精査する。指摘を見て、直すものは保管庫で直し、コピーし直して 3 からやり直す
   - 精査は使用量が多いので、教材を足したときや大きく直したときに流す
5. ブランチを作って PR を出す。CI でも検査が走る

## 検査で見つけるもの

`npm run check:content` が、合わないものを「ファイル（`content/` からのパス）・どの決まりに合わないか」の一覧で出し、1つでもあれば失敗で終わる。

- 置いてはいけないファイル・フォルダ（「.」で始まるもの、ノートと画像以外）
- 名前と並びに合わないもの（一番上に教材のフォルダ以外がある、`index.md` から入口へのリンクがない、入口・ガイドがない、入口が2つある、章の番号の抜け・重なり・01 から始まらない、教材のフォルダの直下に章でないノート・画像がある）
- フロントマターに `title` がない・空のノート
- リンク切れ（ノートへの相対リンク、相対パスの画像）
- アプリで表示できない書き方（コードの外の `[[ ]]`・`![[ ]]`）

## 精査の観点

`/content-review` で、サブエージェント（`content-reviewer`）がこの節を読んで精査する。観点を変えるときは、ここだけを直す。機械的に見つけられるもの（上の「検査で見つけるもの」）は、精査では見ない。

### A. 内容の正しさ

- 公式ドキュメントなどの情報源と、食い違いがないか（コマンド・オプション・設定の名前、API、仕様、数値、料金、試験の範囲など）
- 古くなった情報がないか（版が上がって変わった機能・名前など）
- 必要なら Web で公式ドキュメントなどを読んで確かめる。検索の言葉にノートの文章を貼らない（ノートの中身を外へ送らない）
- 情報源が見つからず確かめきれなかったものは、指摘と分けて書く

### B. スマホでの読みやすさ

- 列の多い表（横にはみ出す）。列を減らす、箇条書きにするなどを勧める
- 長いコードの行（横にスクロールしないと読めない）
- 深すぎる見出し（`####` より深いなど）、見出しのない長い区間
- 長すぎる段落、詰め込みすぎた箇条書き
- 説明のない図・画像だけに頼る説明

### C. 教材としてのまとまり

- ガイド（`00_ガイド.md`）と入口の章の一覧が、実際の章とそろっているか（抜け・余り・題のずれ）
- 章の型（各章の節の並び）がそろっているか
- 用語・表記の揺れ（同じものを章ごとに別の言い方で書いていないか）
- 章の順番どおりに読んで分かるか（まだ出ていない用語を前提にしていないか）

## 精査が返すもの

- 指摘ごとに：ノート（`content/` からのパス）・場所（見出し）・観点（A/B/C）・何が問題か・どう直すとよいか
- 指摘がなければ「指摘なし」
- 確かめきれなかったものは、指摘と分けて書く
- 精査ではノートを変えない（直すのは保管庫のほう）
