# コンテンツフォルダ（保管庫）の決まり

学習用の保管庫（`learning-vault`。アプリとは別の非公開のリポジトリ）に教材を置くときの決まり。ノートの正本は保管庫にあり、アプリはビルドのときに保管庫を読む（アプリのリポジトリに `content/` はない）。この文書で「コンテンツフォルダ」と書くのは、保管庫の `notes/` フォルダの中のこと。アプリと検査は `notes/` の外を読まない。

- 決まりに合うかは、検査のコマンド（`npm run check:content -- <保管庫>/notes`）が機械的に確かめる。本番・プレビューのビルド（Vercel）の最初にも走り、合わないものがあればビルドが失敗する（本番は前の版のまま残り、Vercel から失敗のメールが届く）
- ノートの中身（内容が正しいか、スマホで読みやすいかなど）は、精査のコマンド（`/content-review`）でサブエージェントが確かめる
- 保管庫の一番上（`notes/` の外）には、`README.md`・`.claude/`（AI への指示）など、何を置いてもよい。アプリにも出ず、検査もしない
- 保管庫とアプリをつなぐ手順（鍵・Deploy Hook）は `docs/vault.md`

## 置いてよいもの

- ノート（`.md`）と、アプリが表示できる画像（png・jpg・jpeg・gif・webp・svg。拡張子の大文字・小文字は問わない）だけ
- 名前が「.」で始まるファイル・フォルダ（`.obsidian/`・`.github/`・`.gitignore`・`.claude/` など）は、どの階層にあっても検査で飛ばし、アプリにも出ない。置いてよい
  - 理由は `docs/design.md` の「保管庫には決まりに合うものだけを置く」

## 名前と並び

コンテンツフォルダの下を、資格・実践・基礎・スポットの4つの分類に分ける。資格・実践・基礎には教材を、スポットには単発の資料を置く。分類の名前と順は `src/lib/note-categories.json` の1か所にあり、ノートの一覧と検査の両方が使う（変えるときはアプリを直す）。

### 一番上（`notes/` の直下）

- ホームの `index.md` と、フォルダ「資格」「実践」「基礎」「スポット」だけを置く。4つのフォルダは、ないものがあってもよい
- ノートの一覧では、資格・実践・基礎・スポットの順に並ぶ
- `index.md` には、資格・実践・基礎のすべての教材の入口（`index_<教材名>.md`）へのリンクを置く（スポットのノートにはリンクしなくてよい）

### 資格・実践・基礎

| 分類 | 置く教材 |
| --- | --- |
| 資格 | 試験のための教材 |
| 実践 | 仕事のための教材 |
| 基礎 | 土台の教材 |

- 直下には教材ごとのフォルダだけを置く（例：`資格/AWS クラウドプラクティショナー/`）。ファイルを置かない
- 教材のフォルダの決まりは、下の「教材のフォルダの直下」「下のフォルダ」

### スポット

- 直下にはテーマのフォルダだけを置く（例：`スポット/GCP/`）。ファイルを置かない
- テーマのフォルダの中は、どの深さにもノートと画像を置ける。入口・ガイド・番号の決まりはない（例：`スポット/GCP/gcloud の認証のつまずき.md`）

### 教材のフォルダの直下

| ファイル | 決まり |
| --- | --- |
| 入口 | `index_` で始まる `.md` をちょうど1つ（例：`index_python基礎.md`）。`<教材名>` はフォルダ名と同じでなくてよい（空白を除く・`_` に変えるなど） |
| 学習ガイド | `00_ガイド.md` |
| 章 | `<2けたの番号>_<題>.md`（例：`01_Pythonの基本と実行のしかた.md`）。番号は 01 から抜けなく続け、重ねない |

- 直下には、上の3種類のほかにファイルを置かない

### 下のフォルダ

- 章でないノートと画像は、教材のフォルダの下のフォルダに置く（`図`・`暗記用`・`演習`・`早見表`・`テンプレート` など。名前は決めず、増やしてよい）
- 下のフォルダのファイル名には、番号の決まりを付けない（`演習/02_模擬問題1_パート1.md` のように、同じ番号を枝分かれで使ってよい）
- 中に置いてよいのは、ノートと画像だけ

### すべてのノート

- フロントマターに、空でない `title` を書く（見出しと一覧の名前に使う）

## 書き方

アプリでは表示できない書き方を使わない。検査で見つける。

- `[[ ]]`・`![[ ]]`（Obsidian のリンクと埋め込み）を、コード・数式の外に書かない。ふつうのリンク `[表示名](../folder/note.md)` と画像 `![説明](図/xxx.svg)` に直す
- 相対リンク・相対パスの画像は、コンテンツフォルダ（保管庫）の中にある先を指す（リンク切れにしない）

## 足し方の手順

教材を足すときも直すときも、保管庫で書いて push する。アプリのリポジトリには何もしない（コミットも PR も要らない）。

1. PC の Obsidian で、保管庫の `notes/` の下の分類（資格・実践・基礎）に教材のフォルダを作る（または直す）。単発の資料は `notes/スポット/<テーマ>/` に置く
2. 資格・実践・基礎に教材を足したときは、`notes/index.md` に、新しい教材の入口へのリンクを足す（スポットは要らない）
3. アプリのリポジトリで `npm run check:content -- <保管庫>/notes`（例：`npm run check:content -- ../learning-vault/notes`）を実行する。一覧に出たものを保管庫で直し、通るまでくり返す
   - `check:content` は `.env.local` を読まないので、フォルダを引数で渡す
   - 画面で確かめるときは `npm run dev`（`.env.local` の `CONTENT_DIR` のフォルダを読む。`<保管庫>/notes` を指しておく）
4. 教材を足したときや大きく直したときは、`/content-review <保管庫>/notes/<分類>/<教材名>` で精査する。指摘を見て、直すものは保管庫で直し、3 からやり直す
   - 精査は使用量が多いので、毎回は流さない
5. 保管庫で commit して main に push する。数分で本番に反映される
   - 検査に通らないと Vercel のビルドが失敗し、本番は前の版のまま残る。Vercel から失敗のメールが届いたら、3 の検査で原因を見て直し、push し直す

## 検査で見つけるもの

`npm run check:content -- <フォルダ>` が、合わないものを「ファイル（`<指定したフォルダ>/<ファイル>`）・どの決まりに合わないか」の一覧で出し、1つでもあれば失敗で終わる。指定したフォルダがなければ、そう出して失敗する。

- 置いてはいけないファイル（ノートと画像以外。「.」で始まるものは見ない）
- 名前と並びに合わないもの（一番上に `index.md` と資格・実践・基礎・スポットのフォルダ以外がある、`index.md` がない、資格・実践・基礎の直下にファイルがある、スポットの直下にファイルがある、`index.md` から資格・実践・基礎の教材の入口へのリンクがない、入口・ガイドがない、入口が2つある、章の番号の抜け・重なり・01 から始まらない、教材のフォルダの直下に章でないノート・画像がある）
- フロントマターに `title` がない・空のノート
- リンク切れ（ノートへの相対リンク、相対パスの画像）
- アプリで表示できない書き方（コードの外の `[[ ]]`・`![[ ]]`）

## 精査の観点

`/content-review` で、サブエージェント（`content-reviewer`）がこの節を読んで精査する。観点を変えるときは、ここだけを直す。機械的に見つけられるもの（上の「検査で見つけるもの」）は、精査では見ない。

### A. 内容の正しさ

- 公式ドキュメントなどの情報源と、食い違いがないか（コマンド・オプション・設定の名前、API、仕様、数値、料金、試験の範囲など）
- 古くなった情報がないか（版が上がって変わった機能・名前など）
- 必要なら Web で公式ドキュメントなどを読んで確かめる。検索の言葉にノートの文章を貼らない（ノートの中身を外へ送らない）
- 情報源が見つからず確かめきれなかったものは、指摘と分けて書く

### B. スマホでの読みやすさ

- 列の多い表（横にはみ出す）。列を減らす、箇条書きにするなどを勧める
- 長いコードの行（横にスクロールしないと読めない）
- 深すぎる見出し（`####` より深いなど）、見出しのない長い区間
- 長すぎる段落、詰め込みすぎた箇条書き
- 説明のない図・画像だけに頼る説明

### C. 教材としてのまとまり

- スポットのノートには、教材の型（ガイド・章の並び）を求めない（C は資格・実践・基礎の教材だけ）
- ガイド（`00_ガイド.md`）と入口の章の一覧が、実際の章とそろっているか（抜け・余り・題のずれ）
- 章の型（保管庫の `.claude/rules/structure.md` の「章の型」）に合っているか。型は「どの章にも置く基本」と「内容に合うときだけ足す要素」に分かれる
  - 基本の節（概要・本文・確認問題・情報源）があるか（確認問題は学習・試験対策の教材だけ）、節の並びが型どおりか
  - 概要に、この章で何ができるようになるか（学ぶと嬉しいこと）が、具体的な場面で書かれているか
  - 足す要素（一言でいうと・例・比較・間違えやすい点・まとめなど）は、章ごとにそろっているかを見ない。代わりに、要るのに無い（ないと分からない・誤解する）、要らないのに有る（形式的に膨らんでいる）、同じことの繰り返し、を指摘する
  - 型を決める前からある教材（どの教材から当てはめるかは、同じファイルの「当てはめ方」）は、型との違いを1つにまとめて書き、章ごとに並べない
- 用語・表記の揺れ（同じものを章ごとに別の言い方で書いていないか）
- 章の順番どおりに読んで分かるか（まだ出ていない用語を前提にしていないか）

## 精査が返すもの

- 指摘ごとに：ノート（コンテンツフォルダ（保管庫）からのパス）・場所（見出し）・観点（A/B/C）・何が問題か・どう直すとよいか
- 指摘がなければ「指摘なし」
- 確かめきれなかったものは、指摘と分けて書く
- 精査ではノートを変えない（直すのは人が保管庫で行う）
