# ライト・ダークを「端末に合わせる」「ライト」「ダーク」の3つから選べる（#33）

## なぜ

- 今は上の帯のボタンでライトとダークを入れ替える2択。一度押すと、端末の設定（OS のダークモード）に合わせる動きに戻せない。OS の設定で昼と夜を切り替えていても、一度押したあとはアプリがついていけない
- シリーズのアプリ memory-forge は「端末に合わせる」「ライト」「ダーク」の3択（最初は端末に合わせる）。共通のパッケージ kinari-md に移す前に、選び方と、`<html>` に付ける印（`data-theme`）を揃える。kinari-md の本文の CSS は `data-theme` を前提にしている（#34）

## 影響する今の仕様

- `docs/specs/display.md` の「ライト・ダーク」（ボタンの形・覚え方・端末の設定への合わせ方・スクリーンショット）
- `docs/specs/notes.md` の「上の帯」（右端のボタンの説明）、`docs/specs/notes.md`・`docs/specs/display.md` の「上の帯の右端に月／太陽のボタン」と書いた状態の行
- `docs/specs/login.md`（ログインの画面には切り替えがない。覚えておいたもので出る。中身は変わらないが、言い方を合わせる）
- `docs/specs/home-screen.md` の「時刻や電池が出る部分の色」（端末に合わせるときも、そのときの bg に合わせる）

## 使う場面

1. 昼はライト、夜はダークに OS が自動で切り替わるスマホで、初めて md-leaf を開く。何も選んでいないので「端末に合わせる」になっていて、夜にノートを読んでいる途中で OS がダークに変わると、開いたままの画面もダークに変わる
2. 前にボタンでダークを選んでいた人が、上の帯の右端のボタンを押す。小さな枠が開き「端末に合わせる」「ライト」「ダーク」が並び、「ダーク」が選ばれている。「端末に合わせる」を押すと、OS の設定に合わせた色にその場で変わり、以後は OS の切り替えについていく
3. 明るい場所で読むために、OS はダークのまま「ライト」を選ぶ。ブラウザを閉じて次に開いてもライトで出て、OS の設定が変わってもライトのまま

## 受け入れ条件

- 上の帯の右端（「Aa」の右）に、ライト・ダークのボタン（読み上げの名前「テーマ」）が出る。上の帯のあるすべての画面（ホーム・ノートのすべての状態）に、スマホでも PC でも出る
- ボタンのアイコンは、選んでいるものを表す：「端末に合わせる」は半分を塗った丸、「ライト」は太陽、「ダーク」は月
- ボタンを押すと、ボタンの右端にそろえて下に小さな枠が開く。見出し「テーマ」と、「端末に合わせる」「ライト」「ダーク」の3つが、それぞれのアイコンつきで並び、今選んでいるものが選ばれた見た目になる
- 3つのどれかを押すと、ページを読み込み直さずにすぐその色になり、ボタンのアイコンも変わる。枠は開いたまま（選び比べられるように）。外を押す・Esc・もう一度ボタンを押すと閉じる。Esc で閉じたときは、ボタンにフォーカスが戻る
- 「端末に合わせる」を選んでいるときは、端末の設定（OS のダークモード）に合わせて出す。開いているあいだに端末の設定が変わったら、それに合わせ直す
- 「ライト」「ダーク」を選んでいるときは、端末の設定が変わっても、選んだもので出る
- 一度も選んでいないブラウザでは「端末に合わせる」になっている
- 前の版でライトかダークを選んでいたブラウザでは、その選んだもの（「ライト」か「ダーク」）が選ばれた状態で出る
- 選んだものは、そのブラウザに覚えておく。別のページへ移っても、ブラウザを閉じて次に開いても、ログアウト・ログインしても、選んだもので出る。別の端末・別のブラウザには引き継がない
- ページを開いた瞬間に、ライトで出てからダークに変わる（またはその逆の）ことはない
- ダークでは、画面の地・文字・枠・リンク・ボタン・ノートの一覧・幕・帯・本文のブロック（コールアウト・コード・表・数式・Mermaid の図）が、ダークの色になる。Mermaid の図は、ボタンで選んだときも、「端末に合わせる」で端末の設定が変わったときも、その場で新しい色で描き直す。ノートの画像は、そのままの色で出す
- ホーム画面に追加したときの、時刻や電池が出る部分の色は、そのとき出している色の bg に合わせる（ボタンで選んだとき・端末の設定が変わったときのどちらも）
- ログインの画面には切り替えのボタンがなく、覚えておいたもの（なければ端末の設定）で出る
- ブラウザに覚えておけないとき（保存が禁止されている・プライベートブラウズなど）も、その場では選んだ色に切り替わり、エラーは出ない。次に開いたときは「端末に合わせる」で出る

## やらないこと

- ライト・ダーク以外の色の組（セピアなど）を足すこと
- 選んだものを端末の間で引き継ぐこと（ログインのアカウントに覚えるなど）
- 設定の画面を作ること（memory-forge は設定の画面に置くが、md-leaf には設定の画面がない）
- 色の値を変えること（ライト・ダークの色はそのまま）

## 調べたこと

- memory-forge は `<html>` に `data-theme="light"`・`"dark"` を付け、localStorage（キー `theme`）に "system"・"light"・"dark" を保存し、`<head>` のスクリプトで最初に描く前に付ける。端末の設定が変わったときも付け直す。選ぶ部品は設定の画面の3つ並び（「端末に合わせる」「ライト」「ダーク」）

## AIが決めたこと

- 3つの名前は「端末に合わせる」「ライト」「ダーク」、枠の見出しとボタンの読み上げの名前は「テーマ」。理由：memory-forge の設定の画面と同じ言葉にそろえる。`docs/overview.md` の用語「ライト/ダーク」とも食い違わない
- 覚えるキーは今の `md-leaf-theme` のまま（memory-forge の `theme` にしない）。理由：前の版で選んだもの（"light"・"dark"）をそのまま引き継げる。アプリごとに別の場所（オリジン）なので、名前が違っても困らない
- ブラウザに覚えておけないときも、その場では切り替える（memory-forge は切り替えない）。理由：今の md-leaf の仕様（`docs/specs/display.md`）のまま。見た目の設定が残らないだけで、その場の読みやすさは変えられるほうがよい
- 枠を開いたまま選び比べられるようにする（選んでも閉じない）。理由：「Aa」の枠と同じ動きにそろえる
- 枠の中は3つを縦に並べ、選ばれている行は surface の地に accent の太字にする（「画面」）。理由：「端末に合わせる」が長く、横に並べると折り返す。選ばれた見た目は「Aa」の枠（accent の太字）に合わせる
- プロトタイプを作らないので、画像を撮る画面と状態は「画面」の表のとおりにする（/dev-build で撮る）
- 「端末に合わせる」で、そのとき出している色の印も `data-theme` に付ける（"light" か "dark"）。理由：CSS と Mermaid の描き直し・時刻や電池の部分の色が、印1つだけを見れば済む（memory-forge と同じ）
