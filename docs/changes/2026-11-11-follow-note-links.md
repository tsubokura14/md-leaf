# ノートの中のリンクから、別のノートへ移れる（#4）

## なぜ

Obsidian で書いたノートは、関係するノートへのリンクでつながっている。今は、ノートの中の相対リンク（`[表示名](../folder/note.md)`）を押すと、`.md` のついた URL へ移ってしまい、いつも「ノートが見つかりません」になる。リンクをたどって読めるようにする。

## 影響する今の仕様

- 変更：`docs/specs/notes.md` の「ノート」（リンクの動き）。ホームの `index.md` の中のリンクも同じ

## 使う場面

1. ノート「開発 / Git ブランチの運用メモ」に `[リリースの手順](リリースの手順.md)` と書いた人が、スマホでそのノートを開き、本文の「リリースの手順」を押す。同じタブで「開発 / リリースの手順」のノートへ移り、上の帯の場所が「開発 / リリースの手順」になり、ノートの一覧でもそのノートが強調される
2. ホーム（`index.md`）に `[Docker のメモ](<開発/Docker のメモ.md>)` と書いた人が、ホームで「Docker のメモ」を押すと、そのノートへ移る。ブラウザの「戻る」でホームへ戻れる
3. 名前を変えたノートへの古いリンク `[古い名前](../開発/古い名前.md)` を押すと、「ノートが見つかりません」の画面が出る。「ホームへ戻る」を押すとホームへ移る

## 受け入れ条件

- ノート（ホームの `index.md` を含む）の中の、`.md` で終わる相対リンクを押すと、そのリンク先のノートへ同じタブで移る
  - リンク先は、リンクを書いたノートのあるフォルダからの相対パスで決める（`../` で上のフォルダ、`./` や何も付けないと同じフォルダ）
  - 一番上の `index.md` へのリンクはホーム（`/`）へ移る
  - パスに空白や日本語があっても移れる（`<開発/Docker のメモ.md>` のような山かっこの書き方も、`%20` のように符号化した書き方も）
  - `note.md#見出し` のように `#` が付いていても、そのノートへ移る（見出しの位置へ移るかは #6 の目次で見出しに印が付いてから。この機能ではノートの先頭）
- 移ったあとの画面は、URL を直接開いたときと同じ（上の帯の場所、ノートの一覧の強調、ページの題）。ブラウザの「戻る」で元のノートへ戻れる
- リンク先のノートがないとき（名前が変わった・消された、コンテンツフォルダの外を指す）は、「ノートが見つかりません」の画面を出す（今の画面のまま：中央にアイコン、「ノートが見つかりません」、「リンク先のノートは、名前が変わったか、消された可能性があります。」、主なボタン「ホームへ戻る」。場所は空で、目次・文字の大きさのボタンは出さない）。「ホームへ戻る」でホームへ移る
- 存在しない URL を直接開いたときも、同じ「ノートが見つかりません」の画面を出す（今のまま）
- ビルドのときに、リンク先がないリンクを見つけたら、ビルドのログに警告を出す。警告には、リンクを書いたノートと、リンク先（書かれたままのもの）を出す。警告があってもビルドは止めない。リンク先がないリンクが1つもなければ、警告は出さない
- `http(s)://` で始まる外へのリンクは、今のまま別のタブで外へ移る
- リンクの見た目は今のまま（accent の色）。リンク先があるかどうかで見た目を変えない
- `[[ ]]` の書き方は解釈せず、文字のまま出す
- ログインしていなければ、リンク先のノートも見えない（今のまま。ログインの画面へ移り、ログインのあとにそのノートへ戻る）

## 画面

画面の見た目は変わらない（リンクの見た目は `docs/specs/screens/note-default.png`、見つからないときは `docs/specs/screens/note-notfound.png` のまま）。プロトタイプは作らない。

## やらないこと

- `[[ ]]` の書き方の解釈（`docs/overview.md` の「やらないこと」）
- 見出しの位置へ移ること（見出しに印を付けるのは #6）
- リンク先がないリンクの見た目を変えること
- `.md` 以外のファイル（画像・PDF など）へのリンク。画像の表示は #5
- ファイル名だけで、別のフォルダのノートを探して移ること（Obsidian の「最短パス」の書き方）。相対パスどおりに探す

## 設計

### 変えるファイル

| ファイル | 変えること |
| --- | --- |
| `src/lib/note-url.ts`（新規） | ノートのパス（`.md` を除いたもの）から URL を作る `noteHref(path)`。各部分を `encodeURIComponent` し、`/notes/` を前に付ける。`src/components/note-tree.tsx` の `noteHref` もこれを使う（URL の形を1か所に置く） |
| `src/lib/note-links.ts`（新規） | リンク先を決める純粋な関数 `resolveNoteLink(href, fromPath)`：リンクを書いたノートのパスと、書かれた href（hast にしたあとの、符号化された形）から、対象外なら `undefined`、対象ならコンテンツフォルダからのパス（`.md` を除く）を返す。外へ出るものは「外」と分かる形で返す |
| `src/lib/markdown.ts` | `renderMarkdown(source, links?)`。`links` は `{ fromPath: string; notePaths: ReadonlySet<string> }`。rehype のプラグインで、対象のリンクの href を書き換え、`data-note-link` を付け、リンク先がないものを `brokenLinks`（書かれたままの href）として返す。`links` がなければ書き換えない（一覧の名前を読むときは要らないため） |
| `src/lib/notes.ts` | `readNote`・`readHome` が、読み込んだ一覧から `notePaths`（ホームの `index` を含む）を作って `renderMarkdown` に渡す。`brokenLinks` があれば、ノートごとに `console.warn` で警告を出す（リンクを書いたノートのファイル名（コンテンツフォルダからのパス）と、リンク先） |
| `src/components/note-body.tsx` | 本文の `div` を、クライアントの部品（`src/components/note-body-content.tsx`、新規）に替える。本文のクリックを1か所で受け、`data-note-link` の付いた `a` なら `router.push(href)` で移る。修飾キー（Ctrl・⌘・Shift・Alt）付き、左ボタン以外、`preventDefault` 済みのクリックは、ブラウザに任せる |
| `e2e/notes.spec.ts`・`e2e/fixtures/content/` | 移る流れのテスト。リンク先がないリンクを書いたノートを足す（撮っている画面に写らないノートに足す） |

### リンク先の決め方

- 対象：href がスキーム（`http:`、`mailto:` など）で始まらず、`/` と `#` で始まらず、`#` と `?` のあとを除いて符号化を戻したパスが `.md` で終わるもの。それ以外は今のまま
- リンクを書いたノートのフォルダ（`fromPath` の親）から、`node:path` の `posix.join` でつなぐ（`./`・`../` を畳む）。`.md` を除いたものが、一覧のパスと大文字・小文字まで同じなら、リンク先がある
- URL：リンク先が一番上の `index` ならホーム（`/`）、それ以外は `noteHref(パス)`。`#` のあとは捨てる（見出しへ移るのは #6）
- リンク先がないときも、同じ形の URL にする（開くと一覧にない URL なので「ノートが見つかりません」になる）。コンテンツフォルダの外を指す（畳んだあとも `..` で始まる）ときは、パス全体を1つの部分として符号化した URL（`/notes/..%2Fx` のような形）にする。`readNote` は一覧の中だけを探すので、どのノートにも当たらない
- 理由：変換をビルドのときに済ませると、押したときに探さずに済み、切れたリンクもビルドの時点で分かる。リンク先の有無は一覧と比べるだけなので、ファイルを読み直さない

### 理由と前提の残し場所

- URL の形（`/notes/` ＋ `.md` を除いたパス）を1か所にまとめた理由：`src/lib/note-url.ts` のコメント
- リンクの書き換えと、外を指すリンクの URL の作り方：`src/lib/note-links.ts` のコメント
- クリックを1か所で受けて移る理由（本文は HTML の文字列なので `next/link` を使えない）と、ブラウザに任せるクリックの条件：`src/components/note-body-content.tsx` のコメント
- 警告をノートを変換するときに出す理由（ビルドのときに全部のノートを変換するので、そこで漏れなく見つかる。`"use cache"` で同じノートは1回だけ変換される）：`src/lib/notes.ts` のコメント
- `docs/design.md` は変えない（決まりは足さない）

## AIが決めたこと

- ノートへのリンクは、ページを読み込み直さずに移る（上の帯・ノートの一覧を残したまま本文だけを変える）。理由：ほかの一覧からノートを開くときと同じ速さ・同じ見え方にする。比べた案：ふつうのリンクのまま（ページ全体を読み込み直すので遅く、スマホで一瞬白くなる）
- `.md` で終わらない相対リンク（フォルダ・画像・PDF など）と、`mailto:` などは、今のまま変えない
- 大文字・小文字は区別する（`Note.md` と `note.md` は別のノート）。理由：本番（Vercel）のファイルの扱いに合わせる
- `/` で始まるリンク（`/開発/note.md`）は、相対リンクではないので変えない
- `#見出し` だけのリンク（同じノートの中）は、今のまま変えない
- 切れたリンクの警告は、ノートごとに1行（`リンク先のノートがありません: <ノートのファイル名> → <リンク先>, ...`）。リンク先は URL の符号化を戻して出す（`%20` で書いたものは空白で出る）。理由：Vercel のビルドログで読みやすくする。比べた案：リンクごとに1行（切れたリンクが多いノートでログが長くなる）、符号化したまま出す（日本語のパスが読めない）
