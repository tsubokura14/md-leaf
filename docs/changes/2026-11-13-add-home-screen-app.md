# スマホのホーム画面に追加して、アプリのように開ける（#27）

## なぜ

スマホで読むたびにブラウザを開いて URL を入れるのが手間。ホーム画面のアイコンから、アドレスバーのない全画面で開けるようにして、アプリのようにすぐ読めるようにする。

## 影響する今の仕様

- 新規：`docs/specs/home-screen.md`（ホーム画面への追加と、そこから開いたときの動き）
- `docs/specs/login.md`：ログインしていなくても返すものに、アプリの名前・アイコンの情報を足す

## 使う場面

1. iPhone の Safari でホームを開いている人が、「共有」→「ホーム画面に追加」を押すと、若葉のアイコンと「md-leaf」の名前で追加される。そのアイコンを押すと、アドレスバーのない全画面でホームが開く
2. Android の Chrome でノートを読んでいる人が、メニューの「ホーム画面に追加」（または「アプリをインストール」）を押すと、同じアイコンと名前で追加される。アイコンから開き、ノートの一覧から別のノートへ移っても、全画面のまま読める
3. ホーム画面から初めて開いた人（iPhone はブラウザとログインの状態が別になる）が、ログインの画面で「Google でログインする」を押すと、Google のログインを済ませたあと、全画面のままホームに戻る

## 受け入れ条件

- スマホのブラウザ（iPhone の Safari、Android の Chrome）で、ホーム画面に追加できる
  - 追加したアイコンは、若葉の印。名前は「md-leaf」
- ホーム画面のアイコンから開くと、アドレスバーなどのブラウザの枠がない全画面で、ホームが開く
- 全画面で開いたまま、ノートの一覧・ノートの中の相対リンク・目次・文字の大きさ・ライト/ダーク・ログアウトが、ブラウザで開いたときと同じように使える。ノートを移っても全画面のまま
- スマホの上の、時刻や電池が出る部分に、上の帯や本文が隠れない
- ログインしていないときに開くと、全画面のままログインの画面が出る。Google でログインすると、全画面のままホームに戻る。許可していないアカウントなら、今と同じく warning の帯が出る
- ログインしていなくても、アプリの名前・アイコン・色の情報（ホーム画面に追加するときにブラウザが読むもの）だけは読める。ノートの一覧・ノートの中身・ノートの画像は、今と同じくログインしないと見られない
- 電波がないときに開くと、ブラウザがいつも出す「つながりません」の画面になる（アプリの中にノートを残さない）
- PC のブラウザで開いたときの見た目と動きは、今と変わらない

## 画面

アプリの中の画面（ホーム・ノート・ログイン）の見た目は変えない。変わるのは、ブラウザの枠がなくなることと、ホーム画面のアイコンだけ。

- アイコン：アプリの印の若葉（ノートの一覧の上の印と同じ形）を、accent の色で、bg の地の中央に置く。ライト・ダークで変えない（ホーム画面のアイコンは1つだけのため）
- 時刻や電池が出る部分の色：画面の地（bg）に合わせる。ライト/ダークを切り替えたら、それに合わせて変わる（ブラウザが対応している場合）
- プロトタイプは作らない（「決まっていないこと」）。合意したスクリーンショットはなく、アプリの中の画面は今の `docs/specs/screens/` のまま。アイコンは、PR で画像を見られるようにする

## やらないこと

- 電波がないときにノートを読めるようにすること（端末にノートを残さない。ログアウトしたあと・許可するアドレスから外したあとも読めてしまうため）
- App Store・Google Play に出すこと
- 通知（プッシュ通知）
- ホーム画面への追加を、アプリの中のボタンや案内で勧めること

## 調べたこと

- Next.js 16 は、`src/app/manifest.ts` でマニフェストを、`src/app/icon.*`・`apple-icon.*` でアイコンを作れる（`node_modules/next/dist/docs/` の metadata の項）。マニフェストの `<link>` に Cookie を付ける指定（`crossOrigin="use-credentials"`）は、Vercel の preview のときだけ付く（`node_modules/next/dist/lib/metadata/` の生成のコード）。本番では Cookie なしで読まれる
- iPhone では、ホーム画面から開いたアプリの Cookie は Safari と別になるので、初めて開いたときはログインし直しになる

### データの変更

### このやり方を選んだ理由

- 色は、トークンファイルから取り出して埋め込む。マニフェスト・アイコンの画像・theme-color は CSS の `var()` を使えず、色の値そのものが要る。TS に色の値を書き写すと、トークンと二重になる（ESLint も `src/` の色コードを止める）。比べた案：ブラウザで `getComputedStyle` から `--c-bg` を読む（`<head>` のスクリプトの時点では CSS が読めていないことがあり、マニフェストとアイコンには使えない）。残す場所：`docs/design.md` の「トークンにない値を書かない」と `src/lib/token-colors.ts` のコメント
- theme-color の `<meta>` はスクリプトが作る。Next.js の `viewport.themeColor` は端末の設定（`prefers-color-scheme`）にしか合わせられず、アプリのボタンで選んだものに合わせられない。React が出す `<meta>` を書き換えると、画面を移ったときに React に戻されうる。残す場所：`src/components/theme.ts` のコメント
- 全画面にするのはマニフェストの `display: "standalone"` と `appleWebApp.capable`。`viewport-fit=cover` は付けない（付けると上の帯が時刻や電池の部分の下にもぐり、`env(safe-area-inset-*)` の余白が要る。付けなければ、ブラウザが時刻や電池の部分をよけて描く）。iPhone の `statusBarStyle` は `default`（`black-translucent` は本文が下にもぐり、時刻の文字がいつも白でライトの地に見えなくなる）。残す場所：`src/app/layout.tsx` のコメント
- `matcher` から外すのは、決まった3つの URL だけ（`docs/specs/` の「決まっていないこと」で決めた案A）。残す場所：`docs/design.md` と `src/proxy.ts` のコメント
- Service Worker は作らない（電波がないときはブラウザの画面のまま。「やらないこと」）

## AIが決めたこと

- ホーム画面のアイコンから開いたときの最初のページは、ホーム（`/`）にする。理由：「最初に開く画面」（`docs/overview.md`）と同じにするため。比べた案：最後に読んでいたノート（覚えておく仕組みが要り、範囲が広がる）
- ホーム画面に出る名前は「md-leaf」にする。理由：ページの題・ログインの画面の名前と同じにするため
- 全画面の向きは固定しない（縦でも横でも読める）。理由：表やコードを横向きで読みたいことがあるため
- アプリの外のリンク（ノートの中の `https://` のリンク）は、今と同じ書き方のままにし、開き方はブラウザに任せる。理由：受け入れ条件を変えず、作りを増やさないため
- 色は、トークンファイルから取り出してビルドに埋め込む（理由は「このやり方を選んだ理由」）
- アイコンの若葉は、画面の印と同じ線の形（`LEAF_PATHS`）を、アイコンの幅の半分ほどの大きさで中央に置く。512 は maskable としても出す（Android がアイコンを丸などに切り抜いても、若葉が切れない余白があるため）。比べた案：塗りつぶした若葉（画面の印と形が変わる）
- 時刻や電池の部分の色を変えるのは、theme-color の `<meta>` をスクリプトで書き換えるやり方にする（理由は「このやり方を選んだ理由」）
- マニフェストの `background_color`・`theme_color` はライトの bg にする（開いた直後、ページを読む前の色。アイコンと同じくライト/ダークで1つだけのため）
- `icon.tsx`・`apple-icon.tsx` の描く部分は、`src/components/app-icon.tsx`（新規）の1つの関数にまとめる。理由：アイコンの決まったファイルからほかの名前を書き出すと、Next.js のルートの型の検査に当たりうるため。比べた案：`icons.tsx` に置く（画面の部品が読み込むファイルに `next/og` が入る）
- theme-color の `<meta>` を書き換えるきっかけは、`<html>` の class の変化を見張る（MutationObserver）1か所にする。理由：開いたとき・端末の設定が変わったとき・ボタンで切り替えたときのどれも `.dark` の付け外しを通るため。比べた案：`toggleTheme` と `applyInitialTheme` のそれぞれで書き換える（同じ処理が2か所になり、片方を直し忘れうる）
