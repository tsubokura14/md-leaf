# content/ の管理ルールと、ノートの中身の精査（#32）

## なぜ

`content/` には、Obsidian の保管庫で（多くは AI と一緒に）作った教材を、手でコピーして入れている。決まりがないので、次のことが起きている。

- 教材を作るときの作業ファイル（各教材のフォルダの `.claude/construction-plan.md`）まで、一緒にコピーされている
- 名前の付け方（`00_ガイド.md`、`index_〇〇.md`、`図`・`暗記用` などの下のフォルダ）は教材ごとにそろっているが、どこにも書かれていない。新しい教材で崩れても気づけない
- ノートの中身（内容が正しいか、スマホで読みやすいか、アプリで表示できない書き方がないか）を確かめる手段がない

## 影響する今の仕様

- 新規：`docs/content-rules.md`（`content/` の決まり。置いてよいもの・名前と並び・足し方の手順・精査の観点）
- `docs/design.md`：「どこでも守る決まり」に、`content/` の検査を足す
- `docs/overview.md`：用語に「教材」を足す

## 使う場面

1. Obsidian で新しい教材「Docker 入門」を作り終えた人が、手順どおりに `content/Docker 入門/` へコピーし、検査のコマンドを実行する。保管庫から一緒に来た `.claude/construction-plan.md` と、番号のない `メモ.md` が、決まりに合わないものとして一覧に出る。直して検査が通ってから、PR を出す
2. 同じ人が、精査のコマンドで「Docker 入門」を精査させる。サブエージェントが教材を読み、「05 章のコマンドのオプションが公式ドキュメントと違う」「03 章の表は列が多く、スマホで横にはみ出す」「06 章がガイドの章の一覧にない」といった指摘を、ノートと場所つきの一覧で返す。ノートは変えない。人は保管庫のほうで直して、コピーし直す
3. 決まりに合わないファイル（`.claude/` など）が入ったまま PR を出すと、CI の検査で止まる

## 受け入れ条件

### 決まり

- `content/` の決まりが1つの文書（`docs/content-rules.md`）にまとまっていて、置いてよいもの・名前と並び・足し方の手順・精査の観点が書いてある
- 置いてよいもの：ノート（`.md`）と、アプリが表示できる画像（png・jpg・jpeg・gif・webp・svg）だけ。名前が「.」で始まるファイル・フォルダは置かない
- 名前と並び（今の教材の形を決まりにする）
  - `content/` の一番上には、ホームの `index.md` と、教材ごとのフォルダだけを置く。`index.md` には、すべての教材の入口へのリンクがある
  - 教材のフォルダには、入口の `index_<教材名>.md`、学習ガイドの `00_ガイド.md`、章の `<2けたの番号>_<題>.md` を置く。章の番号は 01 から抜けなく続く
  - 章でないノートと画像は、教材のフォルダの下のフォルダ（`図`・`暗記用`・`演習`・`早見表`・`テンプレート` など）に置く
  - すべてのノートのフロントマターに `title` がある
- 足し方の手順：保管庫から教材をコピーし、検査し、精査し、PR を出すまでの手順が書いてある

### 検査（決まりに合わないものを見つける）

- コマンド1つで `content/` 全体を検査し、決まりに合わないものを「ファイル・どの決まりに合わないか」の一覧で出す。合わないものがあれば失敗で終わる
  - 置いてはいけないファイル・フォルダ（「.」で始まるもの、ノートと画像以外）
  - 名前と並びの決まりに合わないもの（入口・ガイドがない、番号の抜けや重なり、一番上に教材のフォルダ以外がある）
  - フロントマターに `title` がないノート
  - リンク切れ（今はビルドのときに警告が出るだけ）
  - アプリで表示できない書き方：コードの外の `[[ ]]`・`![[ ]]`（Obsidian のリンクと埋め込み）
- `npm run lint` で、この検査も走る（CI でも走る）
- 今の `content/` は、`.claude/` を外せば検査が通る

### 精査（ノートの中身を確かめる）

- 教材のフォルダ（または1つのノート）を渡すと、サブエージェントが中身を精査し、指摘を一覧で返すコマンドがある
- 指摘には、ノート・場所（見出し）・観点・何が問題か・どう直すとよいかが入る。指摘がなければ「指摘なし」と返す
- 精査では、ノートを変えない（直すのは保管庫のほう）
- 精査の観点は `docs/content-rules.md` に書いてあり、サブエージェントはそれを読んで精査する

### 作業ファイル

- 今の `content/` から、各教材の `.claude/` がなくなっている

## 画面

なし（アプリの画面は変わらない）

- 精査の指摘を、自動で直すこと（ノートの正本は保管庫なので、ここで直すと保管庫とずれる）
- 保管庫から `content/` へ自動でコピー・同期すること（`docs/overview.md` の「やらないこと」）
- 精査を CI で毎回走らせること
- アプリの画面・表示の変更（表示できない書き方が見つかっても、ここではノートの側を直す）
- 今ある5つの教材の中身を、この機能の中で精査して直すこと（仕組みができたあとに、人が順に流す）

### 検査（`scripts/check-content.mjs`）

- 調べる場所は `content/` だけ（`e2e/fixtures/` のテスト用のフォルダは、画面の状態を作るためのものなので対象にしない）。テストからはフォルダを引数で渡す
- 1つの違反は「ファイル（`content/` からのパス）・どの決まりに合わないか」の1行にする。全部を集めてから出す（最初の1つで止めない）
- 調べること
  - 置いてよいもの：名前が「.」で始まるファイル・フォルダ（中は見ない）、`.md` と画像（`src/lib/note-files.ts` と同じ png・jpg・jpeg・gif・webp・svg。大文字・小文字は区別しない）以外のファイル
  - 一番上：`index.md` と、フォルダだけ。`index.md` から、すべての教材の入口へのリンクがある
  - 教材のフォルダの直下：`index_` で始まる `.md` がちょうど1つ、`00_ガイド.md`、`<2けたの数字>_<題>.md` の章。章の番号は 01 から抜けなく続き、重ならない。直下にそれ以外のファイルを置かない（章でないノートと画像は下のフォルダへ）
  - 下のフォルダ：名前の決まりは付けない（「図・暗記用・演習・早見表・テンプレートなど」で、増えうる）。中は置いてよいものだけ
  - すべてのノート：フロントマターに空でない文字列の `title`
  - リンク切れ：`.md` で終わる相対リンクの先にノートがない（コンテンツフォルダの外を指すものも含む）。相対パスの画像の先に画像がない
  - 表示できない書き方：コード・インラインコード・数式・フロントマターの外にある `[[`（`![[` を含む）
- Markdown は unified（remark-parse・remark-gfm・remark-frontmatter・remark-math）で mdast にし、リンクは `link`・`image` の節、`[[` はコードなどの節の位置を伏せた本文から探す。フロントマターは yaml で読む。どれも入っているもので、新しいライブラリは入れない
- リンクの先の決め方（`#`・`?` のあとを捨てる、部分ごとに decode、ノートのある場所から posix で join、大文字・小文字を区別）は、アプリの `src/lib/note-links.ts` と同じにする。`.mjs` から `.ts` を読めないので書き写すことになり、ずれうる。その前提はスクリプトのコメントに書く（影響はこのスクリプトだけ）
- `npm run lint` の中で走るので、CI の「テスト・Lint・型チェック」でも走り、合わないものがあれば失敗する

### 精査（`content-reviewer` と `/content-review`）

- サブエージェントの `tools` は `Read, Grep, Glob, WebFetch, WebSearch`（ファイルを変える道具と Bash を渡さない。ノートを変えないことを、道具の側で守る）。`model` は `claude-opus-5-5`
- 精査の観点は `docs/content-rules.md` を読んで使う（観点をサブエージェントに書き写さない。観点を変えるときは `docs/content-rules.md` だけを直す）
- Web は、事実を確かめるために公式ドキュメントなどを検索・読むときだけ使う。検索の言葉にノートの文章を貼らない（ノートの中身を外へ送らない）
- 教材が大きいときは、ガイドと入口を先に読み、章を順に読む（観点 C は教材全体で見る）
- 返す形：指摘ごとに「ノート（`content/` からのパス）・場所（見出し）・観点（A/B/C）・何が問題か・どう直すとよいか」。なければ「指摘なし」。確かめきれなかったもの（Web で情報源が見つからないなど）は分けて書く
- `/content-review` は `disable-model-invocation: true`（人がコマンドで流すときだけ動く。使用量が多いため）。引数がなければ、`content/` の教材の一覧を示して止まる

### 理由と前提を残す場所

- 「`content/` には決まりに合うものだけを置く」（置いてよいもの・検査を CI で失敗にする理由、`src/lib/notes.ts` の読み方と画像の種類に合わせている前提）：`docs/design.md`。アプリの読み込み（`src/lib/notes.ts`・`src/lib/note-files.ts`）と検査の両方に関わるため
- 名前と並びの決まり、足し方の手順、精査の観点：`docs/content-rules.md`（人が手順として読む文書。理由は短く添える）
- リンクの先の決め方を `note-links.ts` から書き写している前提：`scripts/check-content.mjs` のコメント
- 精査のサブエージェントが道具を絞っている理由・Web の使い方：`.claude/agents/content-reviewer.md` の中

## AIが決めたこと

- 決まりを書く場所は `docs/content-rules.md` にする。理由：`content/` の中に `README.md` などを置くと、アプリにノートとして出てしまう。比べた案：`CLAUDE.project.md`（AI 向けのルールで、人が手順として読む文書には向かない）
- 名前と並びの決まりは、今の5つの教材の形をそのまま決まりにする。今の教材が検査に通るようにするため
- 精査の結果は、`pr-check` と同じく、ファイルを変えずに一覧で返す形にする
- 入口のファイル名は「`index_` で始まる `.md` がちょうど1つ」とし、`<教材名>` がフォルダ名と同じかは見ない。理由：今の教材は `AWS クラウドプラクティショナー/index_AWSクラウドプラクティショナー.md` のように、フォルダ名から空白を除いたり `_` に変えたりしていて、決まった変え方がない。比べた案：フォルダ名から決まった変換で作った名前と比べる（今の5つの教材が通らない）
- 下のフォルダ（`図`・`演習` など）のファイル名には番号の決まりを付けない。理由：`演習/02_模擬問題1_パート1.md`〜`パート3` のように、同じ番号を枝分かれで使っている。比べた案：章と同じく抜け・重なりを見る（今の教材が通らない）
- 検査は `.mjs` のスクリプトにし、アプリの `src/lib/` の TS を読み込まない。理由：Node は拡張子のない import（`./note-url`）を解決できず、TS を動かす道具（tsx など）も入っていない。比べた案：検査を `src/lib/` に TS で書き、Vitest で流す（テストの実行と検査が混ざり、`npm run lint` の一部として失敗の一覧を出しにくい）。新しいライブラリを入れる案（決まりで新しいライブラリはなしとした）
- リンク切れに、相対パスの画像の先がないものも含める。理由：アプリはビルドのとき、ノートのリンクと画像の両方を同じく警告にしている（`src/lib/notes.ts`）。片方だけ見ると、画像のずれに気づけない
- 検査を単独で流すコマンドとして `npm run check:content` を足す。理由：教材をコピーした直後に、ESLint を待たずに流せるようにするため（使う場面 1）
- 検査では、一番上に `index.md` がないことも違反にし、教材のフォルダの直下の `00_` で始まる `00_ガイド.md` 以外のファイル（番号 00 の章）は「章でないもの」として扱う。違反の一覧は `content/` からのパスの順に並べる。理由：決まり（一番上にホームの `index.md` を置く、章は 01 から）をそのまま当てはめたもの
- 精査のサブエージェントの `model` は、別名（`opus`）ではなく `claude-opus-5-5` と書く。理由：人が決めたのは Opus 5.5 で、別名だと版が上がったときに黙って変わる
- `docs/template-files.md` では、2つを「プロジェクトのもの」の雛形の表に混ぜず、別の表にして「テンプレートのものの場所にあるが、集める・取り込むときは `:(exclude)` で外す」と書く。理由：雛形の表は「テンプレートにもあるもの」で、この2つはテンプレートにない。`.claude/agents/`・`.claude/skills/` がテンプレートのものとして載っているので、外し方を書かないと集める対象に入ってしまう
