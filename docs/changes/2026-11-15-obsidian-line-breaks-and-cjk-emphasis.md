# 改行と日本語の強調を、Obsidian と同じように読める（#17）

## なぜ

ノートは PC の Obsidian で書き、アプリで読む。Obsidian では正しく見えるのに、アプリでは崩れる書き方が2つある。書いている間は気づけない。

- 1つの改行が、アプリでは改行にならず、前の行とつながる（確認問題の選択肢が1行になる）
- `**用語（読み）**とは` のように閉じの `**` が括弧・句読点のすぐ後にあると、太字にならず `**` が見える

今は保管庫の書き方の決まり（`learning-vault/.claude/rules/writing.md` の「改行」「強調」）で避けている。アプリの読み方を Obsidian に合わせれば、決まりを気にせずに書ける。

## 影響する今の仕様

- `docs/specs/notes.md` の「ノート」（段落・太字の読み方）

## 使う場面

1. 確認問題で、選択肢を `> ①…` `> ②…` と、`>` だけの行を挟まずに1行ずつ書く。アプリで開くと、Obsidian と同じく選択肢が1行ずつ分かれて見える
2. 本文に `**CI（継続的インテグレーション）**とは` と書く。アプリで開くと「CI（継続的インテグレーション）」が太字になり、`**` は見えない

## 受け入れ条件

- 段落・リストの項目・コールアウトの中・表のセルの外で、1つの改行が改行として見える（Obsidian の既定の「厳密な改行」を切った状態と同じ）
  - 空の行で分けたものは、今までどおり別の段落になる
  - コードのブロックと数式のブロックの中は、今までどおり（書いたまま）
  - コールアウトの1行目（`> [!tip] 題`）の次の行は、今までどおり中身になる
- 閉じの `**`（`*` も）の直前が日本語の括弧・句読点で、直後が文字でも、太字（斜体）になる
  - 例：`**用語（読み）**とは`・`**「〜」**の`・`**終わり。**次`
  - 英語だけの文での太字・斜体の読み方は変わらない
- 目次の見出しの文字も、本文と同じ読み方になる（見出しの中の太字）
- 保管庫で `>` だけの行で選択肢を区切っているノートは、見た目が変わらない

## 画面

画面の作りは変わらない。本文の改行と太字の出方だけが変わる（画面の画像は、実装で撮り直す）。

## やらないこと

- Obsidian のほかの書き方（`[[ ]]`・`==ハイライト==`・`%%コメント%%` など）への対応
- 保管庫の書き方の決まり（`writing.md` の「改行」「強調」）を消すこと。消すかどうかは、本番に出たあとに保管庫の側で決める
- 取り消し線（`~~`）の日本語への対応（保管庫で使っていない）
- `__`・`_` で書いた強調の日本語への対応（remark-cjk-friendly が対象にしていない。保管庫の太字・斜体は `**`・`*` で書く）

## 先に要る機能

なし

## 決まっていないこと

- [x] `__`・`_` の日本語の強調も対応するか（推す答え：外す。比べた案：強調の読み込みを自分で直す…壊しやすい／`**` に置き換える…コードや snake_case を壊す） → 外す

- [x] 1つの改行を改行にするのは、すべてのノートでよいか（推す答え：すべて。保管庫を調べると、1つの改行でつないだ行はほぼコールアウトの中のコードと、選択肢の書き方の名残で、段落の途中で折り返して書いたノートは見当たらなかった。比べた案：フロントマターで切り替える…ノートごとに書く手間が増え、Obsidian とも違う） → すべてのノート
- [x] 新しいライブラリを2つ入れてよいか：remark-breaks（1つの改行を改行にする）と remark-cjk-friendly（日本語の括弧・句読点の前後の強調）（推す答え：入れる。どちらも unified の remark のプラグインで、今の変換に1行ずつ足すだけで、外すのも1行。remark-cjk-friendly は Markdown の仕様に日本語の強調を足す提案の実装で、更新が続いている。比べた案：自分で書く…強調の読み方は Markdown の読み込みの深い所にあり、直すと壊しやすい） → 入れる

## 調べたこと

- 保管庫の `notes/` で、空の行を挟まずに続く文の行を数えた（340 か所）。多くはコールアウトの中のコード（`> ` のあとのコード）で、調べ方が拾いすぎたもの。段落の途中で折り返したノートは見当たらなかった。全部を目で確かめてはいない
- remark-breaks：最後の更新は 2023 年だが、機能が小さく、今の unified 11 で動く
- remark-cjk-friendly：unified 11 向け、2026-11 に更新あり

## 設計

- 変えるファイル：`src/lib/markdown.ts`（変換に2つのプラグインを足す）、`src/lib/markdown.test.ts`（テスト）、`package.json`、`docs/specs/notes.md`（段落の改行と日本語の強調の読み方）、`docs/libraries/remark-breaks.md`・`docs/libraries/remark-cjk-friendly.md`（下書き）、テスト用のノート `e2e/fixtures/content/` に改行と強調の例を足すなら、撮り直す画像
- データの変更：なし
- remark-cjk-friendly は読み込み（micromark）の拡張なので、`remarkParse` の直後に置く。見出しの中の太字も同じ読み込みを通るので、目次（`headings.ts` は HTML の文字を集める）も同じ読み方になる
- remark-breaks は `callouts` の後に置く。`callouts.ts` はコールアウトの1行目を文字の中の `
` で見つけるので、先に改行を `break` にすると1行目の次の行が題に入る。コードと数式のブロックは `text` ではないので変わらない。表のセルは1行なので改行がない
- 理由（順番）は `src/lib/markdown.ts` の `.use()` の隣のコメントに残す
