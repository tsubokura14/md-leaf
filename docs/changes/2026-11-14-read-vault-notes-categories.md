# 保管庫の notes/ の下を、資格・実践・基礎・スポットの4つに分けて読む（#5）

## なぜ

保管庫（`learning-vault`）の一番上に教材を並べていて、設定のフォルダ（`.claude/` など）と教材が同じ階層に混ざっている。また、教材が増えると、試験のための教材・仕事のための教材・土台の教材・単発の資料の区別が一覧から分からない。コンテンツを `notes/` にまとめ、その下を種類で4つに分けたい。今のアプリと検査は「保管庫の一番上がコンテンツフォルダ」「一番上には `index.md` と教材のフォルダだけ」と決め打ちしているので、アプリを先に直す。

## 影響する今の仕様

- `docs/specs/notes.md` の「コンテンツフォルダ」（保管庫のどこを読むか）、「ノートの一覧」（一番上のフォルダの並び）
- `docs/content-rules.md`（保管庫の決まりと検査）の「置いてよいもの」「名前と並び」「足し方の手順」「検査で見つけるもの」「精査の観点」
- `docs/vault.md`（手元の `CONTENT_DIR` の指し方）

## 使う場面

1. AWS の試験勉強をしている人が、スマホで ☰ を押すと、一覧のいちばん上に「資格」「実践」「基礎」「スポット」の4つのフォルダが並ぶ。「資格」を開くと「AWS クラウドプラクティショナー」などの教材のフォルダがあり、章を開くと、上の帯の場所に「資格 / AWS クラウドプラクティショナー / 第01章 …」と出る
2. 保管庫で GCP の単発のメモ `notes/スポット/GCP/gcloud の認証のつまずき.md` を書いて push した人は、入口やガイドを作らなくても、検査に通って本番に出る
3. 保管庫を組み替えるとき、`notes/資格/` の直下に教材ではないノートを置いたまま push すると、検査に落ちて本番は前の版のまま残り、どのファイルがどの決まりに合わないかが Vercel のビルドのログ（と手元の `npm run check:content`）に出る

## 受け入れ条件

### 読む場所

- 本番のビルドは、保管庫の `notes/` フォルダの中をコンテンツフォルダとして読む。`notes/` の外（保管庫の一番上の `README.md`、`.claude/` など）は読まず、検査もしない
- 保管庫に `notes/` がないときは、本番のビルドは失敗し（本番は前の版のまま）、ログに「保管庫に notes/ フォルダがありません」と出る
- 手元の `npm run dev`・`npm run check:content` は、今と同じく `CONTENT_DIR`（または引数）で指したフォルダをコンテンツフォルダとして読む。手元の保管庫を読むときは、`<保管庫>/notes` を指す
- URL・画像の URL・リンクの決め方は、コンテンツフォルダ（`notes/`）からのパスで、今と同じ決まり。たとえば `notes/資格/AWS クラウドプラクティショナー/01_なぜクラウドか.md` は `/notes/資格/AWS クラウドプラクティショナー/01_なぜクラウドか` で開く

### 一番上（`notes/` の直下）

- 置けるのは、ホームの `index.md` と、フォルダ「資格」「実践」「基礎」「スポット」だけ。4つのフォルダは、ないものがあってもよい
- ほかのファイル・フォルダがあれば、検査で「一番上には index.md と、資格・実践・基礎・スポットのフォルダだけを置く」と出る
- `index.md` がなければ、今と同じく「一番上にホームの index.md を置く」と出る

### 資格・実践・基礎

- 直下には教材のフォルダだけを置く。ファイルがあれば「資格・実践・基礎の直下には教材のフォルダだけを置く」と出る
- 教材のフォルダの決まり（入口・ガイド・章・下のフォルダ）は今と同じ
- ホームの `index.md` には、資格・実践・基礎のすべての教材の入口へのリンクを置く（今と同じ「`index.md` から入口へのリンクがない」の検査）

### スポット

- 直下にはテーマのフォルダだけを置く（例：`スポット/GCP/`）。ファイルがあれば「スポットの直下にはテーマのフォルダだけを置く」と出る
- テーマのフォルダの中は、どの深さにもノートと画像を置ける。入口・ガイド・番号の決まりはない
- ホームの `index.md` からリンクしなくてよい

### すべての場所で今と同じもの

- 置いてよいのはノートと画像だけ、名前が「.」で始まるものは飛ばす、フロントマターの `title`、リンク切れ、`[[ ]]` の検査

### ノートの一覧

- 一番上の4つのフォルダは、資格・実践・基礎・スポットの順に並ぶ（ないものは飛ばす）。それより下の並びは今と同じ（フォルダが先、名前の順）
- 上の帯の場所には、今と同じくフォルダの名前とノートの名前を「 / 」でつないで出す（一番上のフォルダの名前「資格」なども入る）

## 画面

見せ方（部品・色・レイアウト）は変えない。一番上のフォルダが4つの分類になり、資格・実践・基礎・スポットの順に並ぶだけ。プロトタイプは作らない（人が確かめた）。テスト用のコンテンツフォルダ（`e2e/fixtures/`）を新しい形に直すので、ノートの一覧が写る画像（`docs/specs/screens/` の一覧・場所が写るもの）は撮り直しになる。

## やらないこと

- 前の URL（`/notes/<教材>/…`）から新しい URL（`/notes/<分類>/<教材>/…`）へ移す仕組み（リダイレクト）。使う人は本人だけで、ブックマークは付け直す
- 前の形（保管庫の一番上に教材）と新しい形の両方を読むこと（「決まっていないこと」で決めた）
- 保管庫の組み替えそのもの（保管庫で、この機能が本番に出たあとに行う）
- 分類ごとの見た目の違い（アイコン・色など）
- 分類の名前をアプリの設定で変えられるようにすること

## 設計

### 変えるファイル

- `src/lib/note-categories.json`（新規）：分類の名前の並び `["資格", "実践", "基礎", "スポット"]` と、教材を置く分類（資格・実践・基礎）・テーマを置く分類（スポット）の分け方。アプリ（`src/lib/notes.ts`）と検査（`scripts/check-content.mjs`）の両方がこれを読む（分類の名前と順をアプリの1か所に持つ）
- `src/lib/notes.ts`：一番上のフォルダだけ、分類の並びの順に並べる。分類にない名前のフォルダは、分類のあとに今の名前の順で並べる（アプリは検査をしないので、検査を通らない形でも表示は壊さない）。2段目より下は今のまま
- `scripts/check-content.mjs`：一番上・資格/実践/基礎・スポットの決まりと文言（受け入れ条件のとおり）。教材のフォルダの検査（`checkCourse`）とノートの検査はそのまま使う。スポットのテーマのフォルダは `collectFiles` で集めるだけ（入口・ガイド・番号を見ない）。ホームからのリンクの検査は、資格・実践・基礎の教材の入口だけ
- `scripts/prepare-content.mjs`：Vercel のビルドでは、保管庫を一時のフォルダ（`.vault/`）に取り、`notes/` があれば `content/` に移して一時のフォルダを消す。なければ「保管庫に notes/ フォルダがありません」と出して exit 1。`.gitignore` に `/.vault/` を足す
- `e2e/fixtures/`：4つのフォルダを新しい形に直す（`content/` では今の「開発」「読書メモ」「日記」を、それぞれ `実践/開発/`・`基礎/読書メモ/`・`スポット/日記/` に移し、`資格/` に小さな教材を1つ足す。ほかの3つも同じ分け方）。`e2e/*.spec.ts` の URL・場所の文字・フォルダの名前を合わせる。一覧と場所が写る画像を撮り直す
- 文書：`docs/specs/notes.md`（コンテンツフォルダ・一覧の並び）、`docs/content-rules.md`（置いてよいもの・名前と並び・足し方・検査で見つけるもの・精査の観点）、`docs/vault.md` と `.env.example`（`CONTENT_DIR=../learning-vault/notes`）、`docs/design.md`（「ノートはビルドの最初に保管庫から取ってくる」「保管庫には決まりに合うものだけを置く」）

### データの変更

- 保存するデータはない。コンテンツフォルダの中の形だけが変わる。URL・画像の URL はコンテンツフォルダからのパスのままなので、`src/lib/note-url.ts`・`note-links.ts`・`note-images.ts`・`src/proxy.ts` は変えない

### このやり方を選んだ理由

- 本番で `notes/` を `content/` に移す（`CONTENT_DIR` を `content/notes` にしない）：「`content/` をサーバーの出力に入れる」と Proxy の作りを変えずに済み、`notes/` の外（`.claude/` など）をサーバーの出力に入れない。理由は `scripts/prepare-content.mjs` のコメントと `docs/design.md` に残す
- 分類の一覧を JSON にする：`.mjs` の検査は `.ts` を読めないので、両方が読める形にする（今は書き写しているが、分類はずれると「検査に通るのに並ばない」が起きるため1か所にする）。理由は `src/lib/note-categories.json` を読む側のコメント（`notes.ts`）と `docs/design.md` に残す
- 分類にない一番上のフォルダも一覧に出す：検査は本番のビルドで止めるので、アプリの側で隠す分かれ道を作らない。理由は `notes.ts` のコメントに残す

## AIが決めたこと

- 検査の文言（「資格・実践・基礎の直下には教材のフォルダだけを置く」など）は、今の `RULES` の書き方に合わせて決めた
- スポットの直下にノートを置けないようにした（テーマのフォルダを必ず作る）。理由：Issue の「テーマのフォルダで括る」に合わせ、スポットの一覧が単発のノートで埋まらないようにする
- `notes/` の外は検査しない。理由：アプリが読まない場所なので、保管庫の一番上に `README.md` などを置いてもよい
- 分類の一覧は `src/lib/note-categories.json` に置く。理由：`.mjs` の検査と `.ts` のアプリの両方が読める。比べた案：`.mjs` に置いて TS から読む（型が付かない）、両方に書き写す（ずれうる）
- 分類にない一番上のフォルダも、分類のあとに名前の順で一覧に出す。理由：検査でビルドを止めるので、アプリに隠す分かれ道を作らない。比べた案：一覧から外す
- 本番では保管庫を `.vault/` に取り、`notes/` を `content/` に移す。理由：「`content/` をサーバーの出力に入れる」と Proxy を変えずに済む。比べた案：Vercel だけ `CONTENT_DIR=content/notes` を使う（出力の追跡を変える要りがあり、`notes/` の外も出力に入る）
- テスト用のコンテンツフォルダは、今のフォルダを分類の下に移し、`資格/` に小さな教材を足す。理由：今のテストの中身を保ったまま、4つの並びを確かめられる
- 最初の3つ（検査の文言・スポットの直下・`notes/` の外）と、プロトタイプを作らないことは、2026-11-14 に人が「このままでよい」と確かめた
