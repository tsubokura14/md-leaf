# 見た目の決まり

## トークン

- トークンファイル：`src/styles/tokens.css`（`src/app/globals.css` から読み込む）
- コードでもプロトタイプでも、トークンにない値（`p-[13px]`、`#3366ff` など）を使わない。`npm run lint` で見つかる
- 色はライトとダークで2組あり、同じトークン名で切り替わる。画面のコードでライト・ダークを分けて書かない

## 雰囲気

「紙と若葉」。生成りの紙に明朝で、本を読むように長い文章を落ち着いて読める見た目にする。差し色は若葉の緑を1色だけ使う。
- 理由：目的が「スマホで読みやすく見る」ことなので、情報の多さより、文字の大きさと行間の広さを優先する

## 色の使い分け

| トークン | 使う場面 |
| --- | --- |
| bg | 画面の地。ノートの一覧・目次の面も同じ色 |
| surface | コード、図、表示中の部品の押したとき（hover）、読み込み中の灰色の枠 |
| text | 本文 |
| muted | 補足の文字、場所（パンくず）、アイコン（アプリの印の若葉を除く）、目次の小見出し |
| border | 区切り線、見出しの下線、枠 |
| accent | リンク、今開いているノート（一覧での強調）、主なボタン、アプリの印（若葉のアイコン）。1画面の主なボタンは1つだけ |
| on-accent | accent の上の文字 |
| note・tip・warning・danger・abstract・important・caution | コールアウトの種類ごとの色（7色）。左の太線と見出しの文字に使い、地はその色を薄くしたもの。danger はエラーの帯にも使う |
| code-keyword・code-string・code-comment | コードのハイライト |
| overlay | 一覧・目次を開いたときの、うしろを暗くする幕 |

## 余白と並べ方

- 余白はトークンの段階（4px 刻み）だけを使う
- 本文の幅は prose の幅までにする。目次を右に出す広い PC（xl 以上）では、目次の左を埋めるよう wide の幅まで広げる
  - 理由：1行が長すぎると、明朝の長文は読みにくい
- スマホでは、本文の左右の余白と、コールアウト・コードの内側の余白を狭くする（PC では広く戻す）
  - 理由：スマホの狭い幅では、余白が広いと折り返しが増えて読みにくい
- 対応する幅：スマホ（主）と PC
  - スマホ：上の帯（☰・場所・目次・ライト/ダーク）＋本文。ノートの一覧は ☰ で左から、目次はボタンで下から出す
  - PC（幅 lg 以上）：ノートの一覧を左に常に出し、☰ を出さない
  - 広い PC（幅 xl 以上）：目次を本文の右に常に出し、目次のボタンを出さない
- 上の帯は、スクロールしても上に固定する

## 文字

- ノートの本文と見出しは明朝（font-body）。ボタン・一覧・目次・表・案内などの画面の部品はゴシック（font-ui）。コードは等幅（font-mono）
  - 理由：読むものと操作するものを書体で分けると、本文に目が向きやすい。表は細かい文字が多く、明朝だと読みにくい
- 見出しは3段階まで：ノートの題（text-2xl）、h2（text-xl、下に区切り線）、h3（text-lg）。h4 以下は text-base の太字
- 本文は text-base、行間は relaxed
- 字間は詰めない（かな・約物は正方形の枠のまま。palt などで詰めない）
  - 理由：句読点のあとが窮屈に見えるより、等幅に並ぶほうが読みやすいと判断した
- 見出しの上の余白は、本文の段落の間より広くするが、広げすぎない（h2 の上は space-8 程度）

## 部品の使い分け

- コールアウト：左に太線、薄い地、見出しにアイコンと題（題がなければ種類ごとの日本語の題）。折りたたみ（`> [!note]-`）は、見出しの右に矢印を出し、最初は閉じておく（閉じているときは右向き、開くと下向き）
  - 見出しはゴシックの小さめの太字で、種類の色。中身は本文と同じ明朝
  - 保管庫の決まりの11種類は、それぞれ別のアイコンにし、色は abstract・note・tip・important・warning・caution・danger の7色に分ける。別名は本来の種類と同じ見た目、決まりにない種類は note の見た目（対応は `docs/specs/notes.md` の「本文のブロック」）
  - 理由：意味を分けて使う組（abstract と info、tip と important、warning と caution）は、色も違えば一目で分かる。11色すべてを別にすると似た色が増え、ライト・ダークの両方で見分けを保つのが難しい
  - 薄い地は、種類の色を bg に混ぜて作る（トークンを増やさない）
- コード（ブロック）：surface の地に等幅の文字。色分けは code-keyword・code-string・code-comment の3色だけで、ほかは text の色。長い行は折り返さず、枠の中で横にスクロールする
- 文の中のコード：薄い地（surface）の等幅の文字。色分けしない
- 表：ゴシックの小さめの文字。見出しの行と各行の間に border の線を引き、縦の線と地は付けない。表の中のコードは地を付けず等幅にするだけ。横に長い表は表の中で横にスクロールする。列の幅は文字数の段階（短い列は折り返さない、中くらい・長い列は table-col-m・table-col-l より狭くしない）で決め、日本語は禁則で折り返す
  - 理由：行の線で区切ってあるので、地を付けると細かく見える
- 図（Mermaid）：surface の地に border の枠。図の線と文字は text の色、強調は accent、字は画面の部品の小さめの字。図は縮めず（縮めると字が読めない）、収まらなければ枠の中で横にスクロールする
  - 理由：縮めると字が読めなくなる
- 数式：本文の中央に置く数式が長ければ、数式の中で横にスクロールする
- 画像：本文の幅に収め、小さい画像は引き延ばさない。角を丸め、border の枠。画像だけの段落では、下に代わりの文字を muted の小さな文字で中央に出す（空なら出さない）
- 本文の中の横に長いもの（コード・表・数式・図）は、それぞれの枠の中でスクロールし、ページ全体は横にスクロールさせない
- ノートの一覧：フォルダは矢印つきで開閉。今開いているノートは accent の薄い地と太字。今のノートを含むフォルダは開いておく
  - フォルダの中は、左に border の線を引いて字下げする。「ホーム」は家のアイコンつき
  - スマホの一覧（☰ で開く）と PC の一覧（左に常に出す）は同じ幅にする
- 上の帯のアイコンのボタン（☰・目次・文字の大きさ・ライト/ダーク）：muted のアイコンで、押すと surface の地
- 目次：h2 と h3 を出し、h3 は字下げして muted にする。押すとその見出しへ移り、スマホでは目次を閉じる
  - 上に「目次」を muted の text-xs の太字で置く。見出しはゴシックの小さめの字（font-ui・text-sm）で、項目ごとに上下の余白をとった行（押しやすい高さ）。押すと surface の地。長い見出しは折り返す
  - スマホ（幅 xl 未満）：上の帯の「Aa」の左のボタンで、下から出す。bg の地に、上の角を丸め、上に border の線と shadow-sheet。上に border の色の短いつまみ。見出しが多いときは、上に幕が少し見える高さで止め、つまみと「目次」を残して見出しの並びだけをスクロールする
  - 広い PC（幅 xl 以上）：本文の右に、地も枠も付けずに置く。本文の題の高さにそろえ、スクロールしても上の帯のすぐ下に残る。本文と目次を合わせた幅で中央に寄せる
- 主なボタン（「ホームへ戻る」など）：accent の地に on-accent の文字
- それ以外のボタン（「もう一度読み込む」「Google でログインする」）：bg の地に border の枠
- 開閉する部品（一覧・目次）は、幕（overlay）の外を押すか Esc で閉じる
- 文字の大きさ：上の帯の「Aa」から、小さな枠（popover）を出す。本文の文字の大きさを px の値（「17px」など）で並べ、押すとすぐ本文に反映する。外を押すか Esc で閉じる。ノートを表示しているときだけ出す
  - 「Aa」はゴシックの太字。枠は「Aa」の右端にそろえて下に出し、bg の地・border の枠・角丸・shadow-popover。見出しは muted の小さな太字。選択肢は surface の地の中に横に並べ、選ばれているものは bg の地に accent の太字、ほかは muted。px の値は等幅
  - 選択肢の px の値は1か所の一覧にまとめ、値を足せば選択肢が増えるようにする。見出しなどの大きさは、本文の大きさに倍率をかけて決める
  - 理由：「小・大」のような名前だと、段階を足すたびに名前を考え直すことになる。px なら値を足すだけで済む
  - 変えるのは本文（ノートの中）の文字だけで、上の帯・一覧・目次などの画面の部品は変えない
  - 理由：読みにくいのは本文で、部品まで大きくすると、スマホで一覧や帯が窮屈になる
- ログアウト：ノートの一覧のいちばん下に、ログイン中のメールアドレスと「ログアウト」ボタンを置く。確認は出さず、押したらログインの画面へ移る
  - 理由：取り消せない操作ではなく、もう一度ログインすれば元に戻るため

## 状態の見せ方

- 読み込み中：表示される形の灰色の枠（スケルトン）を、ゆっくり点滅させる
- エラー：本文の上に danger の帯を出し、理由と「もう一度読み込む」ボタンを置く
- 0件・見つからない：画面の中央に、アイコン・見出し・説明を出す。戻る先があればボタンを置く
- 許可していないアカウント：ログインの画面に warning の帯を出す
- 帯（エラー・許可していないアカウント）：見出しは text の色の太字、本文は muted。warning・danger の色は、薄くした地と枠だけに使う
  - エラーの帯は、見出しの左に丸に「!」のアイコンを置く

## 文言

- 案内・エラーは、ですます調。ボタンは「〜する」「〜へ戻る」のように動詞で終える
- 画面の名前や部品の呼び方は `docs/overview.md` の用語にそろえる（ノート、目次、ノートの一覧）
